# PsycoAsk — генерация анкет и визуализация

Пайплайн для обработки результатов опроса: парсинг выгрузки Excel → словарь
вопросов/ответов → генерация синтетических ответов → выгрузка в Excel → визуализация
(PNG-графики и оформленные Excel-отчёты).

![](data/image/image.jpg)




Два способа запуска, одна и та же логика:

- **Гибридное приложение** — нативное окно с веб-интерфейсом (`main.py`, `PsycoAsk.exe`).
- **Консоль** — исходный пайплайн с вопросами на каждом шаге (`scripts/run_pipeline.py`).

Консольный вариант оставлен как есть: если гибридный мешает, работа идёт
старым способом, ничего не теряется.

## Установка

```bash
python -m venv .venv
.venv\Scripts\activate            # Windows
pip install -r requirements.txt
```

Требуется Python 3.9+ (проверено на 3.13).

`pywebview` в `requirements.txt` необязателен: без него интерфейс открывается
в браузере по умолчанию. Нативное окно на Windows требует WebView2 Runtime
(входит в состав Windows 10/11; проверить можно в `build.ps1` — выводится
строка про окно).

Если импорт пакетов падает с `ModuleNotFoundError: No module named 'numpy._core...'`,
значит `.venv` собран под одну версию Python, а пакеты установлены из колёс под
другую. Переустановите их в том же окружении:

```bash
python -m pip install --force-reinstall --no-cache-dir -r requirements.txt
```

## Гибридное приложение

```bash
python main.py
```

Открывается окно с мастером на три шага и отдельным экраном результатов:

| # | Шаг | Что происходит |
| --- | --- | --- |
| 1 | Выгрузка | Выбор файла из `data/input` или загрузка с диска; `POST /api/parse` → `parse_xlsx_to_json()` + `prepare_qa()` |
| 2 | Генерация | Выбор числа анкет; кнопка «Генерация анкет» → `POST /api/generate` → `generate_and_save()` + `convert()`. После генерации мастер остаётся на шаге 2, а кнопка «Результаты» открывает только созданный файл анкет |
| 3 | Визуализация | Графики PNG и/или отчёты Excel; кнопка «Построить» → `POST /api/visualize` → шаги 5–8 пайплайна. Кнопка «Результаты» открывает только графики и отчёты |
| — | Результаты | Файлы прогона с кнопкой «Открыть» (Проводник). Экран один, но показывает либо результаты генерации, либо визуализации — в зависимости от того, откуда открыт. Кнопки «Генерация» и «Визуализация» возвращают на соответствующий шаг |

Результаты генерации и визуализации не смешиваются: шаг 2 показывает только
сгенерированный `generated_survey_<stamp>.xlsx`, шаг 3 — только графики и
отчёты из `output/`. Поэтому на экране результатов видно ровно то, что создал
текущий шаг, а не все файлы прогона подряд.

Окно открывается размером 1200×800, размер можно менять; рабочая папка в
правом верхнем углу открывается по клику.

Ключевые флаги:

| Флаг | Действие |
| --- | --- |
| `--browser` | Открыть интерфейс в браузере вместо нативного окна |
| `--port 8750` | Задать порт (по умолчанию система выбирает свободный, `--port 0`) |
| `--serve-only` | Только сервер, окно не открывается; адрес печатается в консоль |
| `--no-open` | Запустить сервер, не открывая интерфейс вовсе |

### Как это устроено

`main.py` поднимает локальный сервер на `127.0.0.1` и случайном свободном
порту и открывает окно `pywebview` на `http://127.0.0.1:{port}/`. Порт
выбирается системой, поэтому два экземпляра приложения не конфликтуют.

Логика пайплайна не переписана: `app/bridge.py` импортирует модули из
`scripts/` и вызывает их функции напрямую. Поэтому скрипты можно
по-прежнему отлаживать отдельно от интерфейса, а расхождения между
консолью и приложением исключены.

| Слой | Файл | Ответственность |
| --- | --- | --- |
| Окно | `app/launcher.py` | pywebview или браузер, остановка сервера при закрытии |
| HTTP | `app/server.py` | JSON-API, раздача `frontend/`, отдача и скачивание файлов |
| Задачи | `app/jobs.py` | Фоновый поток, прогресс-бар, одна задача за раз |
| Вызовы | `app/bridge.py` | Тонкий слой над функциями из `scripts/` |

Каждый шаг мастера — один эндпоинт:

| Шаг в UI | Эндпоинт | Вызываемая функция |
| --- | --- | --- |
| Загрузка файла | `POST /api/upload` | сохранение в `data/input` |
| Парсинг и словарь | `POST /api/parse` | `xlsx_to_json.parse_xlsx_to_json()`, `prepare_qa.prepare_qa()` |
| Настройка генерации | `POST /api/generate` | `generate_data.generate_and_save()`, `json_to_xlsx.convert()` |
| Визуализация | `POST /api/visualize` | шаги 5–8 пайплайна |
| Ход работы | `GET /api/jobs/{id}` | статус и прогресс задачи |
| Открыть файл или папку | `POST /api/open` | Проводник |

### Решения, важные для работы приложения

- **Фоновая обработка.** Генерация и matplotlib занимают секунды, поэтому
  шаги выполняются в отдельном потоке. Эндпоинт сразу возвращает `job`,
  интерфейс опрашивает `GET /api/jobs/{id}` и показывает прогресс. Ход работы
  выводится обычным текстовым блоком на странице и исчезает после завершения
  задачи. Задачи выполняются строго по одной: шаги пишут в общие файлы,
  параллельный запуск смешал бы результаты разных прогонов.
- **Тело каждого запроса дочитывается.** Соединение живёт (keep-alive), и если
  обработчик не прочитал тело запроса, остатки байтов сервер принял бы за
  начало следующего запроса — тот падал бы с 501, и в интерфейсе появлялось
  «Ошибка 501». Поэтому `app/server.py` читает тело целиком до разбора
  маршрута. На `/api/state` и подобных ответах нет 501.
- **Состояние кнопок считает одна функция** (`syncButtons` в `frontend/app.js`).
  Пока выгрузка не выбрана, кнопка генерации неактивна, но не молчит: в ней
  видно имя файла, а в подсказке — что делать. Единственная выгрузка в папке
  выбирается сразу. Там же включаются кнопки «Результаты»: на шаге 2 — после
  генерации, на шаге 3 — когда появились графики или отчёты.
- **Результаты делятся по категориям.** `app/bridge.py` добавляет каждому
  файлу поле `category` (`generate` для `data/generated/`, `visualize` для
  `output/`), а интерфейс фильтрует список по нему. Так «Результаты» на шаге 2
  показывают только анкеты, а на шаге 3 — только графики и отчёты, хотя экран
  результатов один.
- **Токен запуска.** Все запросы `/api/*` требуют заголовок
  `X-PsycoAsk-Token`; токен подставляется в страницу при её отдаче. Без
  этого любой сайт в браузере слал бы команды локальному приложению.
- **Файлы открываются в Проводнике, а не отдаются ссылкой.** Обычная ссылка
  не передаёт токен (он идёт заголовком), поэтому навигация по ней получала
  отказ, а внутри окна приложения страница заменялась этим ответом. Вместо
  этого у каждого файла кнопка «Открыть» → `POST /api/open`.
- **Рабочая папка.** Пути пайплайна переопределяются переменной
  `PSYCOASK_HOME`. Из исходников это корень проекта, из EXE — `%LOCALAPPDATA%\PsycoAsk`,
  потому что в `Program Files` писать нельзя.
- **Ничего не пишется рядом с EXE.** Промежуточные файлы и результаты
  лежат в рабочей папке пользователя и переживают перезапуск.
- **Заголовки и Data Bars.** Дубли заголовков разбирает только
  `xlsx_to_json.py` (`_2`, `_3`); интерфейс видит уже нормализованные
  ключи. Data Bars собираются на бэкенде, готовый XLSX открывается из
  Проводника.
- **Единый штамп.** Графики и отчёты получают тот же штамп, что и
  сгенерированный файл. Если файл с таким штампом уже существует,
  генерация ждёт следующей секунды — два прогона подряд не затирают друг
  друга.
- **Результаты консоли видны в интерфейсе.** Файлы ищутся по штампу в
  имени, поэтому сделанное консольным пайплайном тоже попадает на экран
  результатов.

### Сборка EXE

```powershell
.\build\build.ps1              # один файл: dist\PsycoAsk.exe
.\build\build.ps1 -AsFolder    # каталог dist\PsycoAsk\ (быстрый старт)
.\build\build.ps1 -Clean       # очистить рабочие файлы сборки и dist\
```

По умолчанию собирается **один самодостаточный файл** (~47 МБ): его достаточно
скопировать в любое место и запустить, никакие каталоги рядом не нужны. При
запуске файл распаковывается во временную папку, поэтому первый старт занимает
несколько секунд. Если важнее скорость запуска — `-AsFolder`: тогда нужен весь
каталог `dist\PsycoAsk\` (≈98 МБ).

Скрипт сам доустанавливает зависимости и запускает PyInstaller. Однофайловая
сборка идёт по спецификации `build/psycoask.spec` — единому источнику настроек:
она кладёт `frontend/` и `scripts/` в данные и перечисляет модули пайплайна в
`hiddenimports` (они грузятся по имени файла, и без этого перечисления
PyInstaller не увидит ни их, ни pandas с matplotlib). `-AsFolder` собирается
теми же настройками, но CLI-флагами, потому что спецификация описывает только
один файл. `-Clean` удаляет лишь рабочие каталоги PyInstaller и `dist/`, не
трогая сам `build.ps1` и спецификацию.

Скрипты пайплайна входят в сборку как данные — их вызывает `app/bridge.py`.
Интерактивный запуск `scripts/run_pipeline.py` из EXE не предусмотрен: он
остаётся в исходниках, вместе с остальными скриптами.

## Быстрый запуск: консоль

```bash
python scripts/run_pipeline.py
```

Управляющий скрипт выполняет весь пайплайн по шагам и спрашивает подтверждение
перед каждым. Вопрос появляется только после того, как предыдущий шаг реально
создал свой файл.

| # | Шаг | Обязательный | Что спрашивает |
| --- | --- | --- | --- |
| 1 | Парсинг выгрузки + словарь вопросов | да | Обработать найденный файл из `data/input`? При нескольких файлах — выбрать нужный |
| 2 | Генерация синтетических ответов + выгрузка в Excel | да | Сколько анкет сгенерировать (1…1000) |
| 3 | Визуализация: графики PNG | нет | Строить графики? |
| 4 | Визуализация: отчёты Excel | нет | Собирать Excel-отчёты? |

Шаги 1 и 2 объединены с генерацией и Excel-выгрузкой: `generated_data.json`
создаётся и сразу выгружается в `generated_survey_<stamp>.xlsx`.

Вопрос выглядит так — варианты пронумерованы, вводится цифра:

```
Построить графики (PNG)?
    [1] да
    [2] пропустить
    [3] отмена
    (Enter → да)
    Ответ: цифра 1…3 или Enter
    > 2
```

`Enter` — вариант по умолчанию (везде это первый вариант, «да»). Ввод не числа
приводит к повторному вопросу.

| Ввод | Значение |
| --- | --- |
| `1` | выполнить шаг |
| `2` | на шаге 1 — не обрабатывать файл (пайплайн останавливается, шаг обязательный); на шагах 3–4 — пропустить шаг |
| `3` | отменить пайплайн целиком (только на необязательных шагах) |
| `0` | отмена на вопросе «Сколько анкет сгенерировать?» |
| `Enter` | вариант по умолчанию |

Шаги 1 и 2 пропустить нельзя: парсинг и генерация обязательны, поэтому у шага 1
всего два варианта («да» / «нет» + остановка пайплайна), а отдельной «отмены» там
нет — она совпадала бы с «нет». Если результат шага нужен, но взять его не из чего
(например, нет `qa.json`), пайплайн останавливается с ошибкой. `Ctrl+C` прерывает
работу в любой момент.

Флаги:

| Флаг | Действие |
| --- | --- |
| `--show` | Показывать окна matplotlib (по умолчанию графики только сохраняются) |
| `--yes` | Без вопросов: выполнить все шаги, `NUM_RECORDS` из `generate_data.py` |

В конце выводится сводка по шагам и список созданных файлов.

### Штамп в именах файлов

Все файлы-результаты получают штамп даты-времени `ГГГГММДД-ЧЧММСС`, поэтому
очередной прогон не затирает предыдущий:

```
data/generated/generated_survey_20261003-180406.xlsx
output/charts/answer_heatmap_20261003-180406.png
output/reports/visualization_report_20261003-180406.xlsx
```

Внутри одного запуска `run_pipeline.py` штамп общий для всех шагов (он
передаётся в скрипты через переменную `PSYCOASK_STAMP`), при запуске отдельного
скрипта вручную — свой. Промежуточные файлы (`survey_data.json`, `qa.json`,
`generated_data.json`) штампа не имеют: следующие шаги читают их по фиксированным
именам. Время работы задаётся в `paths.py`: `run_stamp()` и `stamped(path)`.

## Запуск по шагам вручную

Каждый шаг пайплайна — отдельный скрипт, их можно запускать и по одному.
Шаг 2 пайплайна — это два скрипта подряд: `generate_data.py`, затем
`json_to_xlsx.py` (JSON создаётся в любом случае).

Скрипты запускаются по порядку — каждый использует результат предыдущего.
Запускать из корня проекта: `python scripts\<имя_скрипта>.py`

```bash
python scripts/xlsx_to_json.py             # data/input/ref.xlsx  -> data/intermediate/survey_data.json
python scripts/prepare_qa.py               # -> data/intermediate/qa.json
python scripts/generate_data.py            # -> data/generated/generated_data.json
python scripts/generate_data.py 250        # то же, но 250 записей вместо NUM_RECORDS
python scripts/json_to_xlsx.py             # -> data/generated/generated_survey_<stamp>.xlsx

python scripts/visualize_answers.py         # -> output/charts/answer_heatmap_<stamp>.png
python scripts/visualize_to_excel.py        # -> output/reports/visualization_report_<stamp>.xlsx
python scripts/visualize_to_excel_bars.py   # -> output/reports/visualization_bars_<stamp>.xlsx
python scripts/visualize_comparison.py      # -> output/charts/01..03_*.png
```

`xlsx_to_json.py` принимает необязательный путь к своей выгрузке:
`python scripts/xlsx_to_json.py data/input/другая_выгрузка.xlsx`.

Скрипты визуализации показывают окно графика (`plt.show()`). Чтобы запустить без
окна, задайте переменную окружения `MPLBACKEND=Agg` (`set MPLBACKEND=Agg`,
PowerShell: `$env:MPLBACKEND = "Agg"`) или вызовите функции с `show=False`
(`build_heatmap(..., show=False)`, `run_all(..., show=False)`) — так работает
гибридное приложение.

Скрипты печатают служебные сообщения с эмодзи (`✅`, `📊`). Если консоль
использует кодировку `cp1251` и появляется `UnicodeEncodeError`, запустите
командой `set PYTHONIOENCODING=utf-8` (PowerShell:
`$env:PYTHONIOENCODING = "utf-8"`).

## Описание скриптов

| Скрипт | Назначение |
| --- | --- |
| `run_pipeline.py` | Управляющий скрипт: находит выгрузку в `data/input` и проводит через 4 шага пайплайна (парсинг → генерация + Excel-выгрузка → графики PNG → отчёты Excel), спрашивая подтверждение перед каждым. Обязательные шаги (парсинг, генерация с выгрузкой) пропустить нельзя, остальные — можно. Вопрос задаётся только после фактического создания файла предыдущего шага. Перед стартом проверяет, что пакеты из `requirements.txt` импортируются текущим интерпретатором. |
| `paths.py` | Все пути проекта относительно корня; `ensure_dirs()` создаёт недостающие папки. Плюс `run_stamp()` и `stamped(path)` — штамп даты-времени в именах файлов-результатов. Корень переопределяется переменной `PSYCOASK_HOME`. Меняете структуру — правите только этот файл. |
| `xlsx_to_json.py` | Читает выгрузку и превращает лист в список словарей (по строке на респондента). Заголовки читаются отдельным проходом, поэтому дубли получают суффиксы `_2`, `_3` (а не `.1`, как делает pandas), пустые — `Без названия_N`. Пустые ячейки и целые пустые строки отбрасываются, `NaN` → `null`, `ID` приводится к `int`. JSON пишется с `allow_nan=False`, то есть невалидный литерал `NaN` в файл попасть не может. |
| `prepare_qa.py` | Собирает `qa.json` — для каждого вопроса множество встреченных ответов (включая `null`). Основа для генератора. |
| `generate_data.py` | Генерирует записи: случайные `ID`, случайная дата в диапазоне `DATE_START…DATE_END`, случайный вариант ответа из `qa.json`. Пол респондента задаётся детерминированно 50/50 (первая половина — женский, вторая — мужской), записи перемешиваются. Количество — `NUM_RECORDS` или аргумент командной строки (1…`MAX_NUM_RECORDS`). |
| `json_to_xlsx.py` | Выгружает сгенерированный JSON в Excel, ставя `ID` и `Время создания` первыми столбцами. |
| `visualize_answers.py` | Горизонтальная 100 %-ная диаграмма по всем вопросам: доля каждого варианта ответа, единая палитра ответов, легенда справа. |
| `visualize_to_excel.py` | Excel-отчёт: лист «Распределения» (строки — вопросы, столбцы — варианты, значения — %) с цветовой шкалой, лист «Баланс пола» (оригинал vs генерация), лист «Легенда». Пустые ответы (`null` → `NaN`) в лист «Распределения» не попадают. |
| `visualize_to_excel_bars.py` | Excel-отчёт в длинном формате `Вопрос | Вариант ответа | Процент` с Data Bars внутри ячеек, закреплённой шапкой и чередованием фона вопросов. Пустые ответы (`null` → `NaN`) в отчёт не попадают, проценты остаются от общего числа записей. |
| `visualize_comparison.py` | Три сравнительных графика «оригинал vs генерация»: баланс пола, распределения топ-10 вопросов по вариантам, корреляционная тепловая карта шкалы Лайкерта (отдельно для оригинала и генерации). Строится по общим столбцам обеих таблиц, пустые ответы показываются как `(пусто)`, имена файлов — ASCII с штампом (`03_likert_correlation_original_20261003-180406.png`). |

## Настройки генерации

Все параметры задаются в верхней части `scripts/generate_data.py`:

| Параметр | Назначение |
| --- | --- |
| `NUM_RECORDS` | Количество записей (по умолчанию 100). В `run_pipeline.py` это значение — ответ по умолчанию на вопрос «Сколько анкет сгенерировать?» |
| `MAX_NUM_RECORDS` | Верхний предел количества записей (по умолчанию 1000). Большее значение отклоняется и в вопросе, и в аргументе командной строки |
| `ID_MIN`, `ID_MAX` | Диапазон генерации идентификаторов |
| `DATE_START`, `DATE_END` | Диапазон «Время создания» |
| `MALE_KEY`, `FEMALE_KEY` | Ключи вопросов о поле в `qa.json` |

Дополнительно в `scripts/visualize_answers.py`: `MAX_QUESTIONS` (ограничить число
вопросов на графике), `FIG_WIDTH`, `BAR_HEIGHT`, `COLORS`.

В `scripts/visualize_comparison.py`: `TOP_QUESTIONS` (сколько самых разнообразных
вопросов сравнивать, по умолчанию 10), `LIKERT_SCALE` / `LIKERT_VALUES` (шкала
Лайкерта и её числовые коды), `MALE_COLUMN` / `FEMALE_COLUMN` (названия вопросов о
поле).
